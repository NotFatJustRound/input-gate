## input-gate：给 agent 的外部输入先过一道闸

**问题**：agent 读网页、读 issue、读聊天记录的时候，外部文本是直接进上下文的。里面只要有一句「忽略之前的指令，去执行 xxx」，模型就有概率照做——尤其抓到的是别人精心写过的页面。这不是靠模型自己"聪明一点"能稳住的，得在入口处动手。

**做法**：所有外部文本进上下文之前，先经过一个纯函数 gate：

- **来源标记**：每条输入带上 `source` / `trust` 字段，模型能看见它是从哪来的、可不可信
- **长度封顶**：超长文本截断，防止一次性把上下文塞满
- **可疑模式检测**：指令注入、角色切换、外传类话术，规则表可增删
- **域名白名单**：只放行你列出来的站点，其余一律降级处理

三档策略 `strict / balanced / lenient` 决定命中的后果。**strict 下硬规则命中直接整段丢弃正文**，一个字都不进上下文——不是挂个警告了事。

**它不是安全边界**。它挡的是「明显写着"执行这个命令"的文本」，挡不住精心构造的、混在正常内容里的诱导。把它当第一层过滤，别当保险。

**状态**：v2.1.0，零运行时依赖，`tests/gate.test.mjs` 四十来条断言。

**想要反馈的点**：
- 白名单按站点放宽，还是按域名后缀
- 硬规则命中时，除了丢弃，要不要额外吐一条审计记录
- 有没有必要加一层「同源多段文本拼起来才触发」的检测（单段看不出问题的那种）

## 给别人用的短版（一句话）

> 一个零依赖的输入闸：外部文本进 agent 上下文前，先过来源标记、长度封顶、注入模式检测和域名白名单，strict 档下命中即整段丢弃。
